# 08 同一条净值曲线，年化怎么一会儿 26%，一会儿 18%？

> 两个数字都可能出自同一份日收益。看起来只差一个公式，算的却不是同一件事。

## 现象

回测跑完，下一步通常就是算年化。很容易顺手写成这样：

```python
annual_return = (1 + daily_returns.mean()) ** 252 - 1
```

先求平均日收益，再假设每天都赚这么多，复利 252 次。看上去没什么问题。

但本章的合成数据，用这行代码算出 **+26.3%**；按账户实际的起终点净值和经过的日历时间算，CAGR 是 **+18.3%**。

相差 8 个百分点，净值曲线却一分钱都没变。先别急着给策略加分，看看这个公式替你做了什么假设。

## 为什么会这样

### 每天平均赚多少，不等于账户最后赚多少

先不用公式，拿 100 元试一下：

| 时点 | 收益 | 账户里还剩多少 |
|---|---|---|
| 开始 | — | 100 元 |
| 第一天 | −50% | 50 元 |
| 第二天 | +50% | 75 元 |

两天的平均收益是 0%，账户却亏了 25%。第二天的 50% 是在剩下的 50 元上赚的，涨跌百分比的分母已经变了。

前面那行代码把每天的涨跌替换成同一个平均值，跳过了这件事。这个差别通常叫**波动拖累**。算术均值可以描述平均单期收益，但拿它推出来的年化，不能直接当作这段净值的实际 CAGR。

### 再看一下：这笔钱到底放了几年？

复利算对以后，还要确定年数。

本章的例子一共有 1,223 个交易日。除以 252，得到 4.85 年；看起止日期，实际经过了约 4.99 年。同样一笔正收益，被放进更短的时间里，算出的年化自然更高。

所以 CAGR 的年数直接用日历时间：

```python
years = (end_date - start_date).days / 365.25
cagr = (end_equity / start_equity) ** (1 / years) - 1
```

这里的 252 并不是到处都不能用。日波动率和 Sharpe 常按 252 个交易日年化，那是统计口径；算账户这几年复利增长了多少，则要看实际经过的时间。

本章脚本为了演示差别，用的是简化交易日历，不是真实的交易所日历。实际接行情时，CAGR 仍然可以直接从起止日期计算。

### 顺手核对一下 Sharpe

另一个容易写顺手的公式是 `CAGR / 年化波动率`，然后把结果命名成 Sharpe。

[Sharpe](https://web.stanford.edu/~wfsharpe/art/sr/sr.htm) 用的是**单期超额收益的算术均值**和它的标准差。CAGR 则从复利净值计算，两者的分子就不一样；无风险利率不为零时，还要先扣掉同周期的无风险收益。

如果报告里已经有这两个指标，核对各自的公式，比只看最后的数字更有用。别把“CAGR / 波动率应该比 Sharpe 小多少”当成固定等式。

## 最小复现

[`repro/08_arithmetic_annualization.py`](https://github.com/Issac250/ashare-backtest-pitfalls/blob/main/repro/08_arithmetic_annualization.py) 用固定随机种子生成日收益，年化波动约 35%。同一份数据，分别用三种口径算年化：

```bash
python repro/08_arithmetic_annualization.py
```

```text
trading days per year: {2019: 244, 2020: 246, 2021: 245, 2022: 244, 2023: 244}
annual volatility: 35.0%
(1 + mean daily)^252 - 1   (wrong) : +26.3%
compound, calendar years   (right) : +18.3%
compound, years = days/252 (wrong) : +18.8%   (1223 days -> 4.85 'years', calendar says 4.99)
```

- **+26.3%**：用平均日收益推算年化，不能作为这条净值的 CAGR。
- **+18.3%**：用实际复利净值和日历年数计算 CAGR。
- **+18.8%**：用了复利净值，但年数还是按交易日数 / 252 算，收益又被抬高了一点。

这三个数是合成例子的输出，用来展示计算口径。你的策略会差多少，要拿自己的净值算，不能直接套这里的 8 个百分点。

## 怎么防

回测报告里，给“年化收益”留一个明确的口径：如果报的是 CAGR，就从起终点净值和日历时间计算。日均收益推算值也可以保留，但列名要分开，比如 `ann_approx`。

一个简单的检查办法：把报出来的 CAGR 再算回终点，看看能不能对上账户净值。

```python
expected_end = start_equity * (1 + cagr) ** years
```

忽略显示时的四舍五入，这个数应该和 `end_equity` 一致。对不上，就去检查收益、年数和起终点是不是同一段样本。

[`ashare-bt`](https://github.com/Issac250/ashare-bt) 的 CAGR 按日历时间计算，并对极短样本设了年数下限。接自己的日线和选股信号时，也可以对照它的指标实现。
