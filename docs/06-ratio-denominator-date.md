# 06 分子没用未来数据，分母呢？

> 公告金额在当天就知道，拿来相除的市值却可能是事后的。比值也要逐项检查日期。

## 现象

把“事件金额 / 流通市值”超过 3% 的事件分到一组，结果这组之后明显跑输。看起来像发现了“大事件”的负面效应。

但在本章的合成数据里，事件金额和之后的收益没有预测关系。差别是比值的市值取自哪个日期。

## 为什么会这样

假设公告时事件金额是 3 亿元，流通市值是 100 亿元，比例为 3%。公告后股价跌了 30%，市值变成 70 亿元，同一个金额的比例就变成了约 4.29%。

事件本身没有变大，分母变小了。若用这个事后的比例给公告当天分类，已经跌得多的股票就更容易被放进“大事件”组。

再从公告日起计算未来收益，刚才影响分母的下跌，也被包含在这段收益里。分类和结果被同一段价格变化牵到了一起。

供应商提供的比值不一定有这个问题，但列名不会自动告诉你分母的日期。要看字段说明，或拆回金额、股本和价格核对。

## 最小复现

[`repro/06_ratio_denominator_date.py`](https://github.com/Issac250/ashare-backtest-pitfalls/blob/main/repro/06_ratio_denominator_date.py)：生成 20,000 个事件。金额在信号日 t 确定，事件在 t+20 生效，金额不预测前后收益。用信号日市值和生效前一天市值各算一次比例，再按 3% 分组。

```bash
python repro/06_ratio_denominator_date.py
```

```text
flagged 'big event': vendor ratio 25.4% of events, ratio at t 24.7%
big - small forward return, vendor denominator (wrong): -4.01%
big - small forward return, denominator at t   (right): -0.06%
```

事后分母下，“大事件减小事件”的未来收益是 −4.01%；换成信号日分母，结果是 −0.06%。

被分入大事件组的比例却很接近：25.4% 和 24.7%。数量差不多，不代表入选的是同一批股票。

## 怎么防

给分子、分母各写一个取值日期和可知日期，再确认都不晚于策略做决定的时间。公告金额已公开，也不能替市值的日期背书。

重建比值以后，与原字段逐条对照。如果对不上，先查单位、股本范围、价格口径和日期；不一定是重建错，也可能本来就用了不同定义。
