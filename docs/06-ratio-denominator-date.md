# 06 比值的分母也有日期

> 一个比值有两个日期。分子和分母要分别问一遍："这个数在信号日已经知道了吗？"

## 现象

事件研究的结论是"规模大的事件，之后显著跑输"。而实际上，这个事件本身没有任何作用。

## 为什么会这样

**供应商算好的比率，分母常常来自事后。** 拿"某事件规模占流通市值比例"这类字段来说：分子（事件规模，单位是元）在公告时就定了，没有问题；分母却常常是事件生效前一天的市值，那已经是信号日之后的信息了。

**它比一般的未来函数更阴险。** 这份未来信息和被测的收益直接相关。信号日之后跌得多的股票，市值缩水，比例就被抬高，更容易越过"规模大"的门槛；而被测的恰恰是信号日之后的收益。于是跌得多的票被系统性地挑进了"大事件"组，效应完全是凭空造出来的。算一下量级：一只股票跌 30%，分母只剩 0.7，比例就被抬高 1/0.7 − 1 ≈ 43%。

**堵上之后数字没变，也只是运气。** 不堵的话，那个结论本来就不可信，哪怕它碰巧是对的。

## 最小复现

[`repro/06_ratio_denominator_date.py`](https://github.com/Issac250/ashare-backtest-pitfalls/blob/main/repro/06_ratio_denominator_date.py)：20,000 个合成事件。事件规模在 t 日确定，和之后的收益毫无关系。"规模大" = 比例超过 3%。前瞻收益从 t 日起算，包括 t 日到事件生效之间的涨跌。

```bash
python repro/06_ratio_denominator_date.py
```

```text
flagged 'big event': vendor ratio 25.4% of events, ratio at t 24.7%
big - small forward return, vendor denominator (wrong): -4.01%
big - small forward return, denominator at t   (right): -0.06%
```

- **错的数 −4.01%**：用事件生效前一天的市值做分母，"大事件"组看上去显著跑输。
- **对的数 −0.06%**：用信号日的市值做分母，效应消失，和真实情况一致。

注意两种口径下被标记为"大事件"的比例几乎一样（25.4% 对 24.7%），只看标记数量是发现不了问题的。变的是**谁**被标记了。

## 怎么防

1. 供应商算好的比率字段，默认它的分母来自事后，除非你能证明不是。
2. 用自己的行情表在信号日重建分母。比如流通股本可以从成交量和换手率反推：流通股本 = 成交量 ÷（换手率 ÷ 100）。
3. 重建之后，拿自建值和供应商的值对一对口径；对不上，说明重建有错。
4. 给每个输入字段写下"它在哪一刻可以知道"。
