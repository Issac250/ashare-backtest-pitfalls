# 02 早上能买的股票，怎么被下午的涨停挡掉了？

> 订单按开盘价成交，涨跌停判断却用了收盘结果。这道看似保守的检查，也读到了未来。

## 现象

一只股票开盘时没有涨停，下午才涨到涨停价。回测却在早上跳过了它，理由是“当天涨停，不能买”。

去看字段的来源，才发现这个“涨停”是按收盘价算的。字段描述的是下午，订单执行的却是早上。

## 为什么会这样

“今天涨停”没有告诉你**什么时候**涨停。开盘就在涨停价，和开盘正常、盘中才涨停，是两种情况。

本章模型用开盘涨停标记阻止买入，用开盘跌停标记阻止卖出。这是日线上的简化门槛，并不模拟涨跌停价上的排队成交。

如果换成收盘标记，就会拒绝一些开盘之后上涨的股票，也会挡住一些开盘时尚能卖出的股票。下面这组数据，收盘涨停的记录里有 79.1% 开盘没有涨停；收盘跌停的记录里有 78.1% 开盘没有跌停。

本例的收益因此被压低了。但换一个信号，跳过谁、补买谁、剩下多少现金都会变，偏差方向需要重跑，不能靠一句“更保守”判断。

## 最小复现

[`repro/02_limit_gate_timing.py`](https://github.com/Issac250/ashare-backtest-pitfalls/blob/main/repro/02_limit_gate_timing.py)：用合成行情生成 200 只股票，日波动参数为 4%，让涨跌停更容易出现。评分用随机数，持有 50 只，每 5 个信号日调仓，费用设为零；两次只替换涨跌停标记的时间口径。

```bash
python repro/02_limit_gate_timing.py
```

```text
closed limit-up but opened below the limit:   79.1% of 1748 rows
closed limit-down but opened above the limit: 78.1% of 1663 rows
close-based gate (wrong) CAGR: -2.7%
open-based gate  (right) CAGR: +1.9%
```

收盘标记下，CAGR 是 −2.7%；开盘标记下，是 +1.9%。这次用随机评分，是为了把选股预测能力和判断时点的问题分开。

这些结果不意味着换一个字段就能稳定多赚。这里只证明：一个“不能交易”的判断也会改变回测，而且可能用到了订单执行后才知道的信息。

## 怎么防

先查涨跌停字段是按什么价格、什么日期算出来的。订单在开盘执行，标记就要描述开盘；更换板块或历史区间时，涨跌停幅度也要核对。

`ashare-bt` 用 `open_limit_up` / `open_limit_down` 明确时点，对旧名字 `at_limit_up` / `at_limit_down` 会给出错误提示。列名能帮忙，字段的实际计算方式仍要检查。
