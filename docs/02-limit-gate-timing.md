# 02 开盘涨停：用收盘口径判断开盘能不能成交

> 订单在开盘成交，"能不能买"就只能用开盘那一刻知道的信息来判断。拿收盘是否涨停去挡开盘的买单，同样是未来函数。

## 现象

回测按开盘价成交，但"涨停买不进、跌停卖不出"这道闸门，用的是数据里现成的"当日涨停"字段，而那个字段是**收盘价对昨收**算出来的。结果是：两只股票开盘时信息一模一样，只因为其中一只后来收盘涨停了，回测一大早就拒绝买它。

## 为什么会这样

**"涨停"其实有两种。** 一种是开盘就涨停（一字板，或一开盘就封住），确实排不上队；另一种是盘中才涨停，开盘时完全买得到。数据里的涨停字段一般是收盘口径，把这两种混在了一起。在下面的合成数据里，收盘涨停的行有 79.1% 开盘时并没有涨停；收盘跌停的行有 78.1% 开盘时还能卖。

**在这里，偏差方向是悲观的。** 收盘口径的闸门拒绝的，恰好是开盘之后大涨的票，而你本来可以在开盘买到、吃下整段日内涨幅。它还不让你在开盘卖出那些开盘正常、收盘才跌停的票。

**"偏保守"不等于可以不测。** 一条拒绝成交的规则会同时改动好几样东西：少买了谁、替补买了谁、什么时候退出、留了多少现金。净效果只能重跑出来，推理推不出来。"这样更保守"听上去很合理，好像不用测，危险正在这里。没量过的保守和没量过的乐观一样危险。

**反方向的错误也存在。** 完全不设闸门，回测就会买进开盘一字涨停、现实中根本排不上队的股票，偏差变成乐观。

**这个偏差不在公式里，在两个时间戳之间。** 它没有"用到未来收益"，所以只检查有没有用到前瞻收益的代码审查发现不了它。

## 最小复现

[`repro/02_limit_gate_timing.py`](https://github.com/Issac250/ashare-backtest-pitfalls/blob/main/repro/02_limit_gate_timing.py)：用 `ashare_bt.synthetic.make_market` 生成 200 只股票（日波动 4%，让涨跌停经常出现），配一个**随机信号**（没有任何 alpha），持有 50 只、每 5 天调仓、零成本。两次回测只有闸门口径不同。

```bash
python repro/02_limit_gate_timing.py
```

```text
closed limit-up but opened below the limit:   79.1% of 1748 rows
closed limit-down but opened above the limit: 78.1% of 1663 rows
close-based gate (wrong) CAGR: -2.7%
open-based gate  (right) CAGR: +1.9%
```

- **错的数 −2.7%**：收盘口径的闸门。
- **对的数 +1.9%**：开盘口径的闸门。随机信号的正确答案应该在 0 附近。

## 怎么防

1. 每一道"能不能交易"的闸门，都用成交那一刻的数据：开盘成交，就用开盘价对昨收判断涨跌停；只有收盘成交才用收盘价。
2. 一个列名只代表一个时点。`ashare-bt` 只认 `open_limit_up` / `open_limit_down`，传入 `at_limit_up` 这种含糊的旧名字会直接报错，逼你回头检查口径。
3. 审查时，对每一行判断逻辑都问一句：这行代码做决定的时候，当天还有几个小时没发生？
4. "这样更保守"不是不测的理由。
