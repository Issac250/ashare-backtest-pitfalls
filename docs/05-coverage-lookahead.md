# 05 数据覆盖率本身就是未来函数

> 很多数据是供应商按"今天的上市名单"回填的历史，退市公司整行都不在。"只用有数据的行"其实就是"只用不会退市的公司"。

## 现象

接入一份新数据，加上一句 `dropna()` 或 `WHERE x IS NOT NULL`，结果变好了。持仓数、换手、成本都正常，没有任何一个指标报警。

## 为什么会这样

**幸存者偏差**（survivorship bias）：只统计活下来的样本，结论自然偏乐观。这里它换了一身衣服：接新数据时，大家习惯"有就用，没有就跳过"，可"有没有这条数据"这件事本身，可能就带着未来信息。

**先分清这份数据记的是"事件"还是"实体"。**

- **事件档案**：某天发生了什么，按日期存档。公司后来退市，一般不会回头删掉历史记录。
- **实体属性表**：某家公司某项属性的历史。供应商经常拿今天的上市名单回填历史，退市公司整行消失。

行数、时间跨度、代码数量都判断不了这件事。一张表可以有上百万行、覆盖十几年，而退市公司的覆盖率接近 0。

**常规检查为什么抓不到它：**

- **置换检验**（permutation test，打乱分数和股票的对应关系，看真实结果是否超出打乱后的分布）抓不到：置换只打乱分数，宇宙不变，两边带着同样的偏差。
- 和基准比也抓不到：基准是在全宇宙上算的，差距看起来就像 alpha。

## 最小复现

[`repro/05_coverage_lookahead.py`](https://github.com/Issac250/ashare-backtest-pitfalls/blob/main/repro/05_coverage_lookahead.py)：300 只合成股票，其中 45 只在样本期内退市。**合成设定**：退市股在最后 120 个交易日持续阴跌，大多数 A 股退市的路径都是这样。一份"新数据"只覆盖活下来的公司。组合等权持有全部合格股票，每 20 天再平衡，两次回测只有"合格"的定义不同。

```bash
python repro/05_coverage_lookahead.py
```

```text
coverage, survivors:          100.0%
coverage, delisted in sample: 0.0%
universe = rows with the field (wrong) CAGR: +8.4%
universe = every listed stock  (right) CAGR: +5.3%
```

- **错的数 +8.4%**：只保留"这个字段不缺失"的行。
- **对的数 +5.3%**：缺失映射成中性值，所有上市股票都留在宇宙里。

策略本身一个字都没改，多出来的 3 个百分点全部来自"提前知道谁会退市"。

## 怎么防

1. 接入任何新数据，第一件事是按"样本期内有没有退市"分组算覆盖率，而不是数行数。
2. 缺失要映射成中性值（"未知"），不能映射成"排除"。
3. 用新数据在已覆盖的股票之间排序可以；用它决定谁能交易不行。
4. 凡是"加了过滤器、结果变好了"，先跑一次**只加过滤器、不加任何逻辑**的版本。那一行才是真正的对照组。
