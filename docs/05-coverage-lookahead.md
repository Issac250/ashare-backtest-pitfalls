# 05 删掉缺失值之后，怎么连未来的退市股也删了？

> `dropna()` 没改选股公式，却可能改掉整个股票池。先看看那些被删掉的公司是谁。

## 现象

接入一个新字段，清理掉空值，回测变好了。费用、换手和持仓数看起来都正常，也没有明显的前瞻收益列。

但如果这份数据是按今天仍上市的公司补出来的历史，过去退市的公司可能从一开始就不在表里。过滤空值，等于提前把它们排除了。

## 为什么会这样

“没有这个字段”可能只是某一天没采到，也可能是某家公司整段历史都没有。两种缺失，含义差很多。

本章做了一个很直接的设定：后来仍存续的公司，字段全有；样本期内结束上市历史的公司，字段全空。行情里明明有这些公司，接新字段以后却被过滤掉了。

于是，回测在当时就避开了后来表现较差的一组公司。这是数据覆盖带来的**幸存者偏差**，选股分数里不需要出现“将来退市”几个字。

只在剩下的股票里打乱评分，仍然用的是这个被筛过的池子，检查不到原来被排除的公司。和全市场基准的差距，也可能同时包含覆盖差异，不能全算成新字段的贡献。

## 最小复现

[`repro/05_coverage_lookahead.py`](https://github.com/Issac250/ashare-backtest-pitfalls/blob/main/repro/05_coverage_lookahead.py)：生成 300 只股票，其中 45 只在样本期内结束历史，并在最后 120 个交易日设置向下漂移。新字段只覆盖存续公司。两次都等权持有合格股票，每 20 个信号日调仓，只改变合格股票的范围。

```bash
python repro/05_coverage_lookahead.py
```

```text
coverage, survivors:          100.0%
coverage, delisted in sample: 0.0%
universe = rows with the field (wrong) CAGR: +8.4%
universe = every listed stock  (right) CAGR: +5.3%
```

仅保留有字段的公司，CAGR 是 +8.4%；保留当时仍在行情里的全部公司，是 +5.3%。本例的差别来自覆盖筛选。

脚本没有把这个字段用来做有信息的排序，因此可以单独看到股票池改变的影响。真实数据里，缺失原因和缺失股票的表现需要重新检查。

## 怎么防

先比较存续公司和样本期内退市公司的覆盖率，也看缺失是否集中在某些年代、板块或上市阶段。行数很多，不代表覆盖完整。

缺失如何处理，要结合字段含义决定：可以保留“未知”标记，也可以单独报告缺失组。不要把填中性值当成通用解法。重点是让过滤规则只使用当时可知的信息，并报告它删掉了哪些公司。

评估新字段时，再跑一版“只做相同覆盖过滤、不使用字段排序”的对照，看看改善来自排序还是换了股票池。
