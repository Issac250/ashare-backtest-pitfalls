# 12 一个筛选的对照不是 0，是同样大小的随机子集

> 加一个筛选条件，同时会把池子变小，而池子变小本身就要花钱。拿"筛选后 − 筛选前"判断筛选的价值，等于把缩小池子的成本记在了筛选头上。

## 现象

加了一个筛选条件，CAGR 从 31.1% 降到 29.8%，结论是"这个筛选有害"，删掉。可它其实是有用的。

## 为什么会这样

**加筛选同时做了两件事：** 挑出一批股票，以及把池子变小。

**池子变小本身有代价。** 每次调仓能挑的股票少了，组合只能买排名更靠后的名字。拿筛选和"不筛选"比，量到的是"筛选的作用 + 缩池的成本"，两样混在了一起。

**正确的对照是同样大小的随机子集**：从原池子里随机留下和筛选后一样多的股票，再跑一遍。筛选真正的贡献 = 筛选后 − 同样大小的随机子集。随机子集要跑 3 到 5 个，给出一个区间，单个随机种子不能代表一个分布。

**同一个原则还有别的面：对照必须复制真规则的全部机械副作用。**

- 卖出规则的随机对照，要在同一个候选池里对齐触发频率，而不是在全市场里随机。
- 加权方案的等权对照，要施加完全相同的缺失值处理。比如对权重列做了 `dropna()`，那其实也是一次宇宙筛选，否则你比较的是两个不同的宇宙。

## 最小复现

[`repro/12_screen_control.py`](https://github.com/Issac250/ashare-backtest-pitfalls/blob/main/repro/12_screen_control.py)：400 只合成股票，一个特征 x 带来溢价，组合用 `ashare-bt` 买 x 最高的 20 只，每 10 天调仓。**合成设定**：筛选留下 160 只（40%），被剔除的股票真的略差一些（有一点向下的漂移）。所以这个筛选确实有用，只是不足以抵消池子缩小 60% 的成本。

```bash
python repro/12_screen_control.py
```

```text
full pool (400)              CAGR: +31.1%
screened pool (160)         CAGR: +29.8%
random pools (160) x5       CAGR: +23.1%  (range +20.6% .. +25.2%)
screen - full pool        (wrong control): -1.3% a year
screen - same-size random (right control): +6.6% a year
```

- **错的对照**：筛选后 − 全池 = −1.3%/年，结论"有害"。
- **对的对照**：筛选后 − 同样大小的随机池 = +6.6%/年，结论"有用"，而且高于全部 5 个随机池。

## 怎么防

1. 报告任何筛选时，同时报池子大小。
2. 跑 3 到 5 个同样大小的随机子集，Δ = 筛选 − 随机均值，并附上随机结果的区间。
3. 对照组要复制真规则的全部机械副作用：池子大小、触发频率、缺失值处理。
