# 01 收盘后才选出来的股票，还能按收盘价买吗？

> 合成例子里，同一个反转信号，按收盘到收盘算出年化 +19.9%；换成下一开盘成交，只剩 +0.5%。

## 现象

每天收盘，把跌得最多的股票选出来，再算它们从今天收盘到明天收盘的收益。这段代码很顺，曲线也好看。

先停在买入这一步：名单是在收盘以后才知道的，今天的收盘价还能拿来下单吗？

本章还有一个小问题。即使股票本身的价值没有变，最后一笔成交落在买一还是卖一，也会让收盘价显得跌了或涨了。反转信号可能正好挑中了这种跳动。

## 为什么会这样

假设一只股票的中间价是 10 元，买一 9.95 元，卖一 10.05 元。最后一笔主动卖出，记录的成交价可能是 9.95 元；最后一笔主动买入，则可能是 10.05 元。

中间价没动，记录下来的价格却能来回跳。这叫**买卖价差跳动**（bid-ask bounce）。

在本章的合成设定里，开盘和收盘随机落在价差两侧。反转信号容易选到收盘落在低的一侧的股票，下一个收盘落到高的一侧时，就记出一段“反弹”。

但买入价未必是那个低价。用主动成交来想，你买入通常付卖一，卖出拿买一；挂单能不能成交，则需要另一个执行模型。只看最后一笔价格，不能确认这段价差收益能拿到。

再加上信号时点：用收盘结果选股，却让订单按同一个收盘价成交，就把已经结束的价格当成了之后可用的成交价。这个例子用下一开盘成交来避开这一步。

## 最小复现

[`repro/01_close_price_fills.py`](https://github.com/Issac250/ashare-backtest-pitfalls/blob/main/repro/01_close_price_fills.py)：生成 200 只合成股票，潜在价格按随机游走变化，开盘和收盘随机落在价差两侧，价差为 0.5%。按收盘数据选过去跌得最多的 20 只，每天调仓。

```bash
python repro/01_close_price_fills.py
```

```text
close-to-close, no costs (wrong) CAGR: +19.9%
next-open fill, no costs (right) CAGR: +0.5%
next-open fill, default costs    CAGR: -38.2%
```

**+19.9% 和 +0.5% 两次都没扣费用**，主要对比成交时点。加入引擎默认费用后，结果是 −38.2%。

这些是这组合成数据的输出，不能据此说反转策略一定失效。它说明的是：价差跳动和成交假设，可以让没有预测信息的信号看起来有效。

## 怎么防

先在代码里写清楚信号完成的时间，再选之后能使用的成交价格。收盘出信号、下一交易日开盘成交，是这个例子的约定。

如果研究短周期反转，可以再跑一版买卖价差成本，或检查结果对价差宽度有多敏感。收盘到收盘的统计仍可作为研究数据，但不要直接把它报成这笔订单的可实现收益。
