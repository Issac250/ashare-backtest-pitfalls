# 04 股票一股变两股，账户怎么反而亏了一半？

> 除权日价格降了，持股数量和现金也可能变了。只改价格、不改持仓，很容易把账记错。

## 现象

策略和基准选了同样的股票，结果策略却“每年跑输 7%”。先看选股没发现差别，再看估值，问题才出现。

策略用固定股数乘未复权收盘价，基准用了另一套调整口径。它们名字上持仓一样，账却不是按同一种方法记的。

## 为什么会这样

拿送转举例：原来 100 股，每股 20 元，总值 2,000 元。如果变成 200 股、每股 10 元，总值仍是 2,000 元。

代码若只把股价改成 10 元，股数还留着 100，账户就只剩 1,000 元。这笔“亏损”是估值代码算出来的。

现金分红也需要同时看价格和现金。股价除息后下降，不能把收到的现金漏掉；有税费、到账或再投资约定时，还要按自己的账户口径处理。

`ashare-bt` 采用收益率推进持仓价值的近似：用除权口径的 `preclose` 计算 `open / preclose`，再乘 `close / open`。下单算整手时用未复权价格。

这能避免本例里把除权价格变化直接记成持仓损失。但**除权昨收并不等于完整的现金分红账本**，也不能把任意数据源的 `pctChg` 都当成已处理税费和再投资的总收益。对接真实数据时，需要核对字段和估值约定。

## 最小复现

[`repro/04_unadjusted_prices.py`](https://github.com/Issac250/ashare-backtest-pitfalls/blob/main/repro/04_unadjusted_prices.py)：20 只合成股票，首次等权买入后不再调仓。其中 4 只各做一次 10 送 10，全部股票在三个设定日期分红，股息率设为 3%。对照组和引擎都使用脚本里的除权参考价，费用为零。

```bash
python repro/04_unadjusted_prices.py
```

```text
raw shares x raw close  (wrong) CAGR: +8.0%
engine, total return    (right) CAGR: +14.9%
benchmark on pctChg-style returns CAGR: +14.9%
wrong vs benchmark: -7.0% a year  |  right vs benchmark: -0.0% a year
```

固定股数乘原始价格，算出 +8.0%；引擎按除权参考价推进价值，算出 +14.9%，和同口径对照接近。

输出里的 `total return` 是脚本沿用的名称。这里验证的是两套估值口径的差别，以及引擎与对照是否一致；不代表已经验证了现金分红的完整账户处理。

## 怎么防

先选定记账方法：维护实际股数和分红现金，或者使用经过核对的收益率序列。两种方法都要讲清楚分红、送转和税费怎样处理。

找一个已知的送转日做检查：在没有额外价格波动的例子里，持仓价值不应该因为股数翻倍、价格减半而掉一半。策略和基准比较时，也要使用一致的估值和再投资约定。
